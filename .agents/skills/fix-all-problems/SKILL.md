# แก้ไขปันหาทั้งหมด (Fix All Problems Workflow)

## Overview
Skill นี้ใช้สำหรับจัดการและทำความสะอาดระบบทั้งโปรเจกต์เมื่อผู้ใช้เรียกใช้คำสั่ง "แก้ไขปันหาทั้งหมด" โดยเอเจนต์จะต้องทำงานตามขั้นตอนด้านล่างนี้ทีละข้ออย่างเคร่งครัด เพื่อไม่ให้ระบบเดิมเสียหาย
**กฎสำคัญ:** เอเจนต์จะต้องตรวจสอบ Path ของ Active Document (ไฟล์ที่ผู้ใช้กำลังเปิดอยู่) และรันคำสั่งทั้งหมดในโปรเจกต์นั้นเสมอ ห้ามเดาหรือรันในโปรเจกต์อื่นเด็ดขาด
หากพบ Error หรือเกิดข้อขัดข้องในสเต็ปใด ให้ **หยุดการทำงานและแจ้งให้ทราบทันที** ห้ามเดาหรือข้ามสเต็ปเด็ดขาด

## Workflow Steps

### 1. Backup (สร้างจุดเช็คพอยต์ก่อนเริ่มงาน)
รันคำสั่งเพื่อสำรองข้อมูลและสร้างจุดกู้คืนในระบบ:
- `git add .`
- `git commit -m "Auto-backup: Pre-isolation state"` (หรือระบุข้อความอธิบายที่เหมาะสมกับสถานะปัจจุบัน)
- `git tag "backup-pre-isolation"` (หรือระบุชื่อ Tag ที่สัมพันธ์กับสถานะ)

### 2. วิเคราะห์และตรวจสอบลอจิก (Analyze & Test Logic)
- วิเคราะห์หน้าที่และหลักการทำงานของโปรเจกต์ปัจจุบัน
- ทำการทดสอบลอจิก และตรวจสอบการทำงานว่ามีข้อบกพร่อง (Bugs) ตรงไหนหรือไม่
- ตรวจสอบคอขวดหรือโค้ดส่วนที่มีการทำงานล่าช้า (Performance Check)

### 3. แก้ไขปัญหาทั้งหมด (Fix Issues)
- นำปัญหาทั้งหมดที่พบในสเต็ปที่ 2 มาแก้ไขให้ถูกต้อง
- ตรวจสอบให้มั่นใจว่าการแก้ไขไม่ส่งผลกระทบให้ส่วนอื่นๆ ของโปรเจกต์เสียหาย

### 4. ทำความสะอาด (Clean-up)
- ค้นหาและลบไฟล์ขยะที่ชื่อ `_all.js` และ `_gas_check.js` ออกจากโฟลเดอร์ในโปรเจกต์อย่างเด็ดขาด (ใช้คำสั่งค้นหาไฟล์หรือ View Directory) เพื่อป้องกันปัญหาฟังก์ชันซ้ำซ้อน
- หากไม่พบ ให้ข้ามสเต็ปนี้ได้ แต่ต้องตรวจสอบให้แน่ใจแล้ว

### 5. Deploy (อัปเดตขึ้น Production)
- รันคำสั่ง `git push` (เพื่อนำโค้ดที่แก้ไขขึ้น Remote Repository)
- รันคำสั่ง `clasp push -f` (เพื่อผลักดันโค้ดขึ้นไปยัง Google Apps Script)
- รันคำสั่ง `clasp deploy -i <DEPLOYMENT_ID>` เพื่อ Deploy โดย**ต้องใช้ลิงก์เดิมเสมอ** (ห้ามสร้าง Deployment ID ใหม่โดยเด็ดขาด ให้ใช้คำสั่ง `clasp deployments` เพื่อค้นหา Deployment ID ที่เป็นตัวใช้งานปัจจุบัน)

---
**CRITICAL RULE:** การทำตาม Skill นี้ ต้องแจ้งผลให้ผู้ใช้ทราบทุกขั้นตอนอย่างชัดเจน และหยุดทันทีที่เกิดข้อผิดพลาด
